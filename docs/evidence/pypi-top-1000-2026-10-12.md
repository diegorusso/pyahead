# PyPI top-1000 validation, 12 October 2026

The fourth run of the protocol in `docs/pypi-validation.md`. It measures two
changes since the 10 October record: PyAhead 0.7.0, whose analyser is about
twice as fast with byte-identical reports, and a harness fix that probes each
`from A import ...` finding as its source statement says rather than as the
finding's evidence abbreviates it. The corpus, manifest and registry are the
ones the 10 October run used, so every difference below comes from those two
changes.

## Decision

- Prepared by an agent on 12 October 2026. **Approved 12 October 2026 by
  Diego Russo, repository owner and product decision-maker**, on the strength
  of this record and a summary of it. Under the repository's gate convention
  an agent may prepare and verify this evidence but cannot approve it.
- Decision: accept as the current precision record. The three rows the
  earlier records carried as oracle limitations are resolved by the harness
  fix, and the one refutation left is a genuine PyAhead false positive that
  the same fix made observable (below). It stays a documented limitation:
  the shape occurs once in the 1,437 findings checked against source, and
  the only other site a simple rule would match is a correct finding.

**0.7.0's speed** let seven packages that hit the 900 s scan timeout on
10 October finish (`scipy`, `google-cloud-compute`, `kubernetes`,
`phonenumbers`, `ray`, `google-ads`, `datadog-api-client`, in 499–819 s).
They add 13 findings. With the harness fix, 12 of the 13 are confirmed, and
the 13th is not adjudicable because of an import error.

**The harness fix** (`7f7e939`) reads the statement at each from-import
finding's location in the installed source before probing it. It resolves
the three rows the 10 October record carried as oracle limitations:

| row | 10 October | 12 October |
| --- | --- | --- |
| `future` `libpasteurize/main.py:44` (CPY0027) | refuted | confirmed |
| `passlib` `passlib/utils/__init__.py:854` (CPY0008) | refuted | confirmed |
| `future` `future/backports/urllib/request.py:1590` (CPY0108) | refuted | platform-conditional |

- `libpasteurize/main.py:44` binds `main`, `warn` and `StdoutRefactoringTool`
  from `lib2to3.main` and then defines its own `main`. The harness now probes
  `warn`, which the module does not rebind.
- `passlib/utils/__init__.py:854` is `from crypt import crypt as _crypt`
  inside `try/except ImportError`. The harness now compares `_crypt` with
  `crypt.crypt` rather than with `crypt._crypt` (the C helper, which exists);
  and at 3.13, where `crypt` is gone, the import fails as the finding
  predicts and the fallback binds `None`, which is no longer read as a
  version-gated branch.
- `future/backports/urllib/request.py:1590` imports `nturl2path` under
  `if os.name == 'nt':`. The finding is right on Windows; this Linux host
  cannot observe it, and the new reason says so rather than refuting it.

The same reading made 20 from-import rows adjudicable that the earlier
records counted as `module-not-importable`: 19 are confirmed and one is
refuted.

## The open row

`humanfriendly`, `humanfriendly/compat.py:72` (CPY0023, `distutils`):

```python
try:
    # Python 2.
    unicode = unicode
    unichr = unichr
    basestring = basestring
    interactive_prompt = raw_input
    from distutils.spawn import find_executable as which
    from HTMLParser import HTMLParser
    from StringIO import StringIO
    from htmlentitydefs import name2codepoint
except (ImportError, NameError):
    # Python 3.
    unicode = str
    unichr = chr
    basestring = str
    interactive_prompt = input
    from shutil import which
    from html.parser import HTMLParser
    from io import StringIO
    from html.entities import name2codepoint
```

On every Python 3, `unicode = unicode` raises `NameError` before the
`distutils` import, so the import never runs and `which` is
`shutil.which`. PyAhead reports it because its reachability grammar has no
shape for "an earlier statement in this `try` always fails on Python 3".
The refutation is correct. Expressing the shape would need PyAhead to know
which names are Python 2-only builtins; that is analyser work for a later
change, not part of this record.
