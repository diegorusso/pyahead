## What changed since the second 12 October run

Every one of the 999 packages kept its status, and every finding of the
approved run kept its fingerprint and verdict. The run added three
findings, all confirmed:

| package | location | rule | how it arises |
| --- | --- | --- | --- |
| `beartype` | `beartype/typing/__init__.py:183` | CPY0053 `typing.no_type_check_decorator` | import-only: `from typing import (... no_type_check_decorator ...)`, removed in 3.15 |
| `gevent` | `gevent/tests/test__pywsgi.py:1016` | CPY0026 `ssl.wrap_socket` | `sys.path` refinement: reported for 3.13 only |
| `gevent` | `gevent/tests/test__example_wsgiserver.py:65` | CPY0118 `ssl.SSLContext()` | `sys.path` refinement: reported for 3.13 only |

The gevent rows were filtered at high confidence before, because a
`sys.path.insert` in `gevent/tests/test__import_blocking_in_greenlet.py:36`
makes gevent's own `ssl.py` a candidate origin. That insert sits in the
`else` of `if sys.version_info[:2] == (3, 13):`, so on 3.13 it cannot run
and the origin is the standard library; the refined rule keeps the finding
on that target only.

Import-only detection therefore produced one finding across the corpus, and
it is confirmed. One finding is too few to state a precision for the
feature; the record shows it adds no refutation and moves no existing
finding.

## Run conditions

- The sweep ran from a read-only `git archive` copy of `5dbec62` with its
  own locked environment, not from the repository's working tree, so edits
  made there during the run could not reach it.
- Two earlier starts were discarded. The first, from `68f359a`, picked a
  Homebrew Python 3.15.0 installed on the host on 19 October, which the
  probe sandbox does not bind, so probes needing 3.15 crashed; `5dbec62`
  restricts the harness to uv-managed interpreters. The second, from
  `5dbec62` but from the live working tree, was stopped when the repository
  was handed back to another agent. Neither contributes to this record.
